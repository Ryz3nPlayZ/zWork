List pages: one shell, two patterns

Scheduled, Inbox, Projects and Connectors all do the same job: show a collection, let you act on one item, and let you add a new one. This wireframe puts them in one shared page shell. Time-ordered things (Inbox, Scheduled) use the list pattern. Things you open or connect (Projects, Connectors) use the card grid.

One sentence on what shows up here and where it comes from.

+ New thing
  • 1Header. Title 22px left. Subtitle is counts only. Right side: at most one primary button and one icon button. Same on all four pages.
  • 2Toolbar. Optional. Segmented filter on the left, search on the right. Only shown when there is enough to filter (5+ items).
  • 3Section heading. 13px semibold with a muted count. Replaces the uppercase "READ (n)" label and the 17px "More connectors" heading.
  • 4List. One rounded container, rows split by hairlines. 32px icon tile, title, one meta line, trailing status or time. Click the row to open or expand.
  • 5Card grid. 3 / 2 / 1 columns. Icon tile top-left, status top-right, title, 2-line description, footer meta. Overflow menu on hover.
  • 6Empty state. Dashed box, icon tile, one sentence, and the same button label as the header action (no "Create your first X" duplicate wording).

Build order

1. Shared components

PageShell (width, padding, header, toolbar slot), SectionHeading, ListGroup + ListRow, CardGrid + Card, EmptyState, Badge, ConfirmDialog. app/src/components/page/*

2. Move pages onto them

Connectors first (biggest drift), then Inbox, Scheduled, Projects. Behavior and store calls stay exactly as they are.

3. Update design.md

Record 960px width, 22px title (design.md says 28px, no page uses it), list vs grid rule, badge rule, no window.confirm.

4. Later

Project detail page and Settings on the same shell. Analytics and Plan stay as they are for now.
